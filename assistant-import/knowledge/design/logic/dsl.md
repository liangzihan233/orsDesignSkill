# 问卷程序与执行合同

## 实际程序查看与下载（2026-10-23）

逻辑引擎的“实际程序”视图只读展示当前内容编辑和条件设置生成的完整问卷程序，并显示当前草稿及内容指纹。题目属性、图形规则、变量、钩子源码、配置来源均来自同一编译定义。修改配置后实时更新；编译失败显示来源诊断，旧程序立即清空，下载被禁用。

实际程序生成采用单次扫描建立配置来源定位，减少题目较多时打开代码视图的等待；完整代码、来源位置和指纹仍保留。首次加载代码编辑器的时间还受网络及设备性能影响。

“下载程序”保存与当前代码视图完全相同的 JavaScript 文件，文件名包含问卷标识及完整指纹。文件是供平台运行器加载的声明式 SurveyProgram，不是独立网页。此页面没有全卷代码编辑、保存或执行入口；改变行为须回到内容编辑或条件设置。

逻辑引擎默认打开“图形演示”；首次切换到“实际程序”时，才生成当前草稿的代码并加载代码编辑器。“图形演示”只在本页试用规则控件，不保存、不改变答题、实际预览、程序指纹或下载内容。切换视图不会转换代码，刷新或离开页面丢弃本次演示修改。旧全局字段保留在问卷数据中，仍不参与生成与运行。

## 代码编辑联想

题目钩子、显示／下一题代码规则及自动勾选编辑器的联想列表同时展示编码和对应的题目／选项文本。选项按所属题目匹配，确认联想只插入编码；长文本可在联想详情查看。使用方法见[编码联想](http://design.ors-cn.com/agent-help/articles/design/conditions/formula-editor.md#编码联想中的题目与选项文本)。

## 逻辑操作简写

更新于 2026-10-24。当前问卷只在下一题代码中提供控制操作，无须声明入口函数：

| 操作       | 简写         | 可用位置   |
| ---------- | ------------ | ---------- |
| 跳转题目   | `goto("Q3")` | 下一题逻辑 |
| 被筛选结束 | `end()`      | 下一题逻辑 |
| 正常完成   | `complete()` | 下一题逻辑 |
| 配额满结束 | `full()`     | 下一题逻辑 |

下一题的图形与代码顺序保持，第一个明确去向生效。目标可用字符串、变量或拼接，运行时检查类型和存在性；静态目标参与改码和复制维护，动态目标不能安全改写时须人工检查。end/complete/full 不接受参数。校验失败不运行下一题。

旧 show/hide 及显隐决定数组不再作为当前问卷显示入口。显示条件直接写在本题、选项、矩阵行列自己的 displayConditionCode 中，必须是纯布尔表达式。空白无额外限制，false 追加隐藏，true 不解除上层或关联限制。可读全卷答案和确定性纯变量；变量传递依赖也不得读取系统环境、运行进度、时间、随机、外部数据或可变状态。禁止答案写入、网络、DOM、跳转及跨对象显隐。

## 第一阶段执行合同

使用 initializeAnswer(context) 首次预填本题答案，beforeShow(context) 返回本题 view 展示覆盖，validateAnswer(context) 严格布尔校验，resolveNext(context) 决定下一步。现有全卷稳定计算及循环检测保留，尚未切换候选范围计算。

```js
function initializeAnswer(context) {
  if (!Q1.hasAnswer) Q1.setValue("默认内容");
  return { mode: "show" };
}
```

仅首次实际进入且没有恢复或人工回答时执行，返回/恢复/清空不重填；只能写本题，不得同时返回 answer 并调用写方法。默认值先提供，预填可覆盖它；随后执行现有自动勾选、关联和隐藏清理。autoComplete 仍经过系统及自定义校验、下一题与配额检查，不是永久隐藏。

渲染只返回 `{view:{title,note,options,rows,columns}}`，选项和矩阵行列按本题编码寻址。字符串纯文本，富文本采用 `{dwText,dwHtml}` 并经过安全渲染。context.view 提供当前有效项目（含动态行）的 ID/编码/文案。渲染不能写答案、请求网络、改结构或控制流程；每次进入重建展示，恢复不信任旧展示缓存。展示覆盖不改变公式、校验、关联、跨题标签或导出含义。

图形显示编辑将普通选择条件生成为简短表达式，复杂条件生成为布尔函数并打开自定义代码编辑器；题目入口为 `questionVisibility(context)`，子项入口为 `optionVisibility(context)`。二者均须返回 `true` 或 `false`，表达式与函数模式二选一。非空覆盖需确认，不反显手写代码；单题与组内批量共用题目自身字段，旧显示规则需明确清除，不自动迁移。下一题和图形校验规则仍有各自的顺序与重试合同。旧全局 logicScript、surveyDslContent、dwDslAst 和 logicUI 保留数据但不执行。

脚本使用原生 JS、直接公式函数、Q1.value 和集合链式 isin/notin/any。答案写方法仅在本题预填或现有下一题权限内开放；上传、签名等平台管理数据不能用预填伪造。

## 图形条件中的计算变量

题目图形条件可选择条件设置中的变量，普通题和矩阵题均保存稳定变量 ID，修改显示名称不影响绑定。数值提供大小比较，布尔使用开关，文本支持相等、空值和包含，数组支持空值及成员包含。数组成员比较按文本编码匹配数字或字符串，不把对象隐式转换为编码。

变量类型来自定义中的结果类型或可静态确定的表达式；无法确定类型时只提供空值判断。打开编辑器不会执行变量源码。缺失变量、无效运算和运行结果类型错误均明确报错，不视为条件不成立。

## 动态行与富文本变量引用

动态矩阵行和富文本使用条件设置中的同一份变量目录。新引用保存变量 ID，显示名称变化不改变引用；旧的键名引用继续读取现有变量结果。禁用变量不会出现在新增引用菜单中，旧全局逻辑的临时变量不再提供给动态行编辑。

动态矩阵变量应返回文本数组。行身份由文本内容和相同文本出现的次数确定，插入或重排其他文本不会移动已有答案；修改行文本会建立新行身份。重复文本分别生成行，删除的行不继续提交答案。富文本变量引用仍经过现有安全 HTML 渲染。

## 选择题初始化与校验

普通选择题、下拉和图片选择题在本次访问的渲染逻辑之前初始化默认选中。已有草稿优先；取消进入会回滚初始化；用户清空答案后不会反复补回默认选项。单选只取配置中的首个默认选项，多选保留可见的默认选项。自动勾选计算仍具有规则权威。

普通多选、下拉多选和图片多选均先检查选择数量，再执行自定义校验。自动勾选限制操作时，脚本同样不能选择被锁定的选项。下拉的单选／多选配置由同一个规则供组件、脚本和答案提交使用。

## 题目改名与删除

题目编码与题目 ID 绑定。改名后新旧编码都读取同一题，源码保持原样；JS 中与题目同名的局部变量遵守正常作用域。删除题目后旧编码仍保留，不能分配给新题。脚本访问被删除题目会报错，不会转而读取后来创建的题目。

批量改名使用相同约束，可设置未被占用的新编码；不能交换已绑定到不同题目的编码。题目排序只改变展示顺序，不重定向引用。导入数据中的特殊编码通过 `context.questions["编码"]` 读取。

## 输入题规则

内容编辑中选择“数字”时使用数值输入，支持小数；原有整数输入保持非负整数规则。选择“邮箱”时检查基本邮箱格式。已配置的数值上下界（包括 0）和文本长度在系统校验阶段检查，失败后保留答案并等待修改，不执行自定义校验。

输入默认值在渲染钩子之前初始化一次，已有草稿或用户清空答案优先。`Q1.setValue(value)` 复用相同的格式和约束检查，省略参数报错；需要清空时使用 `Q1.clear()`。脚本设值仍受生命周期阶段和题目作答保护约束。

## 设置状态

四个题目逻辑弹窗分别保存“使用自定义逻辑”“使用平台默认”“禁用此逻辑”。恢复平台默认或禁用时保留源码，重新启用仍可继续编辑；清空源码保存会留下禁用记录，CSS、其他钩子和扩展配置保留。无效源码可在禁用状态保留，启用前必须修复语法。

属性编辑记录显式设置的 false、0、空字符串和空数组；打开页面及渲染默认值不会自动产生用户覆盖记录。配置状态仅保存来源与意图，值仍保存在原字段。

## 历史数据边界

旧全局 logicScript、surveyDslContent、dwDslAst 和 logicUI 原始字段保留，但不生成可执行规则。没有旧解释器运行兜底，也不把失效规则自动改写为新逻辑。离线解析工具可用于人工核对；实际行为请在内容编辑和条件设置重新配置并验证。

有效入口中的已移除 API 会明确报错，不自动兼容 ors.questions 或 ors.SUM。当前写法与可运行实例见[JavaScript 逻辑实例](http://design.ors-cn.com/agent-help/articles/design/logic/examples.md)。

## 属性来源与运行状态

实际程序在编译时解析内容编辑的设置状态：显式 `set` 保留 `false`、`0`、空文本和空数组；显式 `inherit` 采用同一题型工厂的默认属性；默认没有值的可选属性从运行定义中移除，但仍保留来源插槽。`disabled` 可关闭布尔能力或设备 CSS，题目 ID、选项 ID、编码和实体列表不能通过属性状态重置，代码与规则使用自己的插槽。

没有状态记录的已有内容继续生效：与平台默认一致的属性在程序中标记为平台来源，其余标为内容来源，不反写成编辑器里的用户修改。CSS 状态变更不会覆盖其他设备 CSS 或题目钩子。若旧数据同时保存了必答别名，显式设置的 `quAttr.isRequired` 作为权威值。

展示、系统答案校验与钩子读取同一编译定义。无效程序显示编译诊断，不提供可执行题目列表；配置变更后重新核对指纹，不使用旧的有效结果替代当前程序。

## 复制题目与选项身份

复制题目时，题目、普通选项、分组内选项、矩阵行列和排序绑定分别创建新身份。题内图形引用、自动勾选目标、行列分组及禁用单元格引用同步指向副本；跨题引用保持原目标；作者 JavaScript 中明确的简写自引用同步指向副本，其他源码保持原样。

分组内选项也有独立的属性来源插槽。被引用选项不存在或嵌套选项身份重复时，程序编译给出诊断，避免悄悄改指其他对象。本规则不扩展可写题型，也不开放原本隐藏的题型面板。

后端题型模板中未使用集合的 `null` 会在载入时作为未配置处理，正常产生题目和选项身份。非空的错误集合类型仍报错，不静默删除题目内容。

## 预览与真实修改

进入外观设计以及切换桌面、平板、手机预览不会自动保存默认设置。实际修改样式后才触发保存；题目代码和保留的历史数据不因预览而被改写。

## 整页模式分页检查

历史 full 配置按当前 answerRenderMode 映射为逐题模式，不增加独立整卷执行路径。点击下一页时，系统及答案校验通过后执行当前页和自动勾选派生答案的配额预检，使用最新答案、发布版本和会话。配额已满或版本变化阻止翻页；预检临时不可用时允许继续，最终收取仍由后端事务检查。重复点击共用同次检查，重置或答案变化后的迟到结果不会推进页面。

## 历史外观脚本

外观设计中的“自定义 Script”只读展示历史源码，编辑预览与公开答题都不执行；键盘输入不保存修改。原始字段按设备保留，其他样式保存不会清除它们，但不进入实际程序和指纹。请把题目行为配置到内容编辑的四个钩子。自定义 CSS 仍按设备编辑、保存和应用。

## 分设备 CSS 与钩子保存

题目 CSS 的桌面、平板和手机代码分别保存，按当前渲染设备选择。切换 CSS 页签后保存会同时保留三个设备的源码；编辑某个钩子或改变其设置状态，不会覆盖其他钩子或 CSS。

“使用平台默认”和“禁用此逻辑”保留未启用的源码，但不编译执行该钩子；其中的 `return false` 或语法错误不会阻止正常答题。重新选择“使用自定义逻辑”时必须通过语法检查，启用的答案校验仍严格返回 boolean。

## 配置来源定位

实际程序的来源目录包含问卷级标题、说明、分组与稳定编码绑定，以及题目、选项、变量、规则和钩子地址。问卷级地址使用 `survey/<稳定问卷ID>/property/<配置路径>`；运行器消费明确设置、继承与禁用后的有效值，编辑草稿原值仍保留。默认值识别与编译过程不读取当前时间或生成新身份。

用户编辑的明确值会保留配置状态，包括清空标题、说明和选项内容，以及删除最后一个分组后的空集合。只读页面初始化、未修改的默认项和编辑器临时标志不会被记为用户覆盖。此状态用于程序来源定位及后续覆盖层，不开放整卷代码编辑。

解除选项绑定会保留明确禁用的来源状态，重新绑定时记录新的有效设置。只编辑某个选项的内容时，记录在该选项的属性地址；增加、删除或排序选项才改变集合来源，避免将单个选项的修改扩大为整组覆盖。

## 异步钩子的受控查询

答案预填、答案校验与下一题钩子可以使用 `async/await` 和标准 `fetch` 查询同源接口。设计预览和公开答题采用相同的同源限制；请求不携带 Cookie 或登录凭证，不跟随重定向，外部域名被拒绝。渲染不能请求网络；变量、显示条件与自动勾选仍为同步纯计算。

异步等待计入单次钩子 10 秒总时限，失败、超时或取消不提交本次效果。设计预览完成生命周期只展示预览结果，不收取答卷。需要鉴权的业务数据应通过专门授权的受控接口提供，脚本不能借用管理端身份。

## 服务端问卷身份

保存与发布时，服务端以真实问卷记录的 ID 绑定程序根身份，客户端 JSON 中省略或修改根 ID 都不能改变归属。发布提升和允许的实时修改会同时核对归属与程序指纹；旧发布记录不原地补写身份，仍需重新发布。题目与选项继续使用各自稳定 ID，排序不改变引用。

## 共享必答属性

题目的必答属性参与系统校验。公开页以同一有效程序配置显示或隐藏必答标记，必答属性的来源状态与其他属性独立保留。系统校验先于自定义答案校验，用户校验仍严格返回 boolean。展示组件不因存在历史属性而自动获得作答能力。

## 展示确认与进度保存

题目完成实际渲染后才确认本次访问已展示。推进等待本题上传和 AI 任务结束，再取得最新答案进入校验；预览也使用同一生命周期。进度保存的成功响应必须有有效的记录 ID 与状态，空回执会阻止推进，不能当作保存完成。

## 对话模式的完成确认

矩阵、上传、多项填空、排序及多选下拉等需要多次操作的题目，在修改答案后继续停留本题，点击“确认并继续”才推进。多选题保留“确认选择”入口。确认统一执行系统校验和题目校验，等待本题上传完成后读取最新答案；可选题允许空答确认，必答题仍由系统阻止空答。预览与公开答题使用相同推进策略。

## 自动完成失败与重试

自动完成题仍需保存进度和通过系统检查。保存失败或当前数据快照失效时显示错误，保留重试入口；不会停在没有题目的等待页。保存失败后的重试复用已确定的下一题去向，不再次执行下一题逻辑；答案变化则必须重新校验。单选题自动规则同时命中多个选项会明确报错，前后端均不接受冲突答案。
