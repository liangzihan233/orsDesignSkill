# 配额概念与收取规则

配额限制特定答案人群的正式完成量。普通配额按选项设置检查点；交叉配额按多个问题组合形成矩阵单元。

## 使用前提与入口

问卷设计 → 配额管理；收取数量与结果见答卷数据 → 配额进度。

## 操作步骤

1. 先完成用作分类的题目与选项编码。
2. 创建普通或交叉配额草稿，设置目标和浮动量。
3. 确认配置完整后启用配额组，等待版本激活完成。
4. 在配额进度核对正式收集和备份数量；发布后仍可使用独立配额更新。

## 按钮与设置

| 名称     | 位置         | 作用与结果               | 可用条件                           |
| -------- | ------------ | ------------------------ | ---------------------------------- |
| 启用     | 配额组行     | 启用当前完整组并生效配置 | 组内有单元、交叉向导完整、非维护中 |
| 关闭     | 配额组行     | 停止该组参与限制         | 非维护中；会按当前批次重分配       |
| 编辑     | 配额组行     | 修改组及目标             | 完成保存后按启用状态激活           |
| 删除     | 配额组行     | 确认后移除组并保存草稿   | 可能触发当前配置重新生效           |
| 恢复激活 | 维护任务区域 | 继续可恢复的切版任务     | 已有任务且当前状态允许             |
| 取消激活 | 维护任务区域 | 请求取消切版并保留旧版本 | 确认后等待任务结束                 |

## 结果与限制

正式提交由服务器对全部命中检查点事务性分配：完成、备份或配额满；测试答卷不预检查、不占额。有限目标之外的浮动量用于备份容量，达到目标加浮动量后为配额满。修改配置或组启停会重新分配当前发布批次的有效正式完成／备份，包括组关闭期间收到的答卷；废弃或转测试仅释放，不自动递补备份。

## 自动化配额边界验收

专用测试流程复制问卷和配额，不复制正式答卷；在隔离数据库预置到N−1后，再用浏览器验证最后一个正式名额、浮动备份和满额。预置通过正式提交与配额分配服务生成答卷及分配明细，可幂等重试。自动化副本仅接受绑定本卷、本发布版本和测试运行的凭证。

后端预置只证明测试准备和数据库分配；报告另外列出实际浏览器答题数量。原卷不注入预置数据，既有答卷不追溯标记。

## 椰子水配额还原范围

本次源配置映射包含19组、442单元：6个完整组启用，13个空组保留为禁用草稿。“大于35岁”按源卷123个实际选项还原；交叉配额9为年龄段×省份×性别的310个不限额单元，检查点在省份题。选择器中未放入实际交叉轴的渠道题不加入维度。依赖旧S2/S5的地区、普通配额7、交叉配额10/11不还原、不测试。

性别31/41，年龄18/18/36，品牌苏萨6、if66，浮动量均为1。启用使用现有历史重分类机制，保留原答案；原有数量超过新容量时保留备份并标记溢出，不能删除历史答卷来满足目标。

## 停止收集时启用配额

配额启用只重分类当前开放发布批次。椰子水本次原卷已停止收集、旧批次已关闭；配额已保存启用，但不会重开收集、创建发布版本或重分类旧批次。历史53条答卷和20条完成分类保持不变，后续正式发布按新批次使用当前配额。
