# 题目通用属性

基本属性仅处理可作答题共有的编码、必答、副标题、倒计时、附件和题目级自定义设置；题目属性处理题型专属配置，包括矩阵选项与布局、AI 访谈、多选数量、图片样式、轮播展示、级联数据以及量表／滑块范围。右侧会按选中题型显示有效控件。

## 使用前提与入口

问卷编辑选中题目 → 右侧属性页签。

## 操作步骤

1. 设置唯一题目编码，离开输入框后进入编码变更审核；检查通过并确认后应用。
2. 选择是否必答、是否显示副标题；需要时填写副标题文字。
3. 配置倒计时与题型属性，保存后测试该题校验。

## 结果与限制

题目级校验与全局逻辑都会影响提交。编码变更会检查公式、脚本和引用；存在无法确定的影响时不能应用。服务器问卷需在审核窗口明确确认后提交，保存成功才替换正式内容；服务器拒绝时保留原问卷，并显示可定位的修正提示。题目属性中没有显示的设置不能从其他题型照搬。

修改题目编码会同步可确定的选项引用。例如 Q1 改为 S1 后，Q1.A1、Q1.A2 的引用同步为 S1.A1、S1.A2；选项自身的 A1、A2 编码和内部身份保持一致。新增“性别”预设同样遵守此规则，不应因题目改码而提示本题选项被其他实体占用。真正属于其他实体或已删除实体的编码仍不能直接占用。

## 四个题目钩子

分别使用答案预填 initializeAnswer、展示 beforeShow、校验 validateAnswer、下一题 resolveNext。允许前置常量、辅助函数和 async/await，保存保留其他钩子及 CSS。

```js
function initializeAnswer(context) {
  return { mode: "show", answer: "首次预填" };
}
```

仅首次实际进入且没有恢复或人工回答时执行；预填可覆盖静态默认值，只能写本题。autoComplete 省略展示，但仍走系统校验、自定义校验及下一题。返回、恢复和主动清空不再次预填。详见[答案预填代码](http://design.ors-cn.com/agent-help/articles/design/properties/common.md#答案预填代码)。

```js
function beforeShow(context) {
  return { view: { title: "本题展示标题", options: { A1: "选项文案" } } };
}
```

view 可含 title、note、options、rows、columns；选项、矩阵行列按本题编码寻址，context.view 提供当前项目 ID、编码和文案（包含已展开动态行）。字符串作为纯文本，富文本使用 `{dwText,dwHtml}` 并经过现有安全渲染。未知目标、字段或错误类型使整次准备失败。不允许写答案、改变结构、网络请求或流程控制。返回 answer、vars、mode 的旧渲染代码需人工拆分，不自动迁移。

展示覆盖仅用于本题渲染，不改问卷定义、公式、校验、关联、其他题的答案标签或导出含义。每次进入完整重建，遗漏字段恢复原文案；刷新恢复时重新生成，不信任存储中的旧展示覆盖。

```js
async function validateAnswer(context) {
  if (!String(context.answer ?? "").trim()) {
    context.setError("请填写有效内容");
    return false;
  }
  return true;
}
```

系统必答、题型和格式校验通过后执行，必须严格返回 boolean；false 保留回答并等待修改，不能修改答案。图形校验的重试和筛选行为独立保留。

```js
function resolveNext(context) {
  return { directive: { type: "default" }, vars: { completed: true } };
}
```

下一题保留现有跨题读取与受控修改能力，不能修改刚校验的当前答案或受保护的历史回答。规则与代码按既有顺序执行，第一个明确去向生效；default 继续后续规则，最后自然顺序推进。去向支持 goto、gotoGroup、finish；结束仍经服务端配额和收取检查。

context 的 question、questionId、answer、answers、formulas、vars、system 等是只读快照；运行变量仅在下一题返回 vars 时提交。预填、校验和下一题可使用宿主允许的受控请求；渲染无网络权限。错误、超时、取消或修订过期不提交部分准备结果。

### 显示、跳转编辑与展示组件

“题目逻辑”保留显示逻辑、跳转逻辑和校验逻辑三个页签。显示逻辑直接使用编号、名称和显示代码表格，本题第一行、下面为选项或矩阵轴；图形编辑仅生成布尔代码，不反显手写代码，覆盖非空内容须确认。组内批量编辑与本题字段同源，不是组准入。旧 visibility 卡及跨题显隐指令会报错，需明确清除后重新编写；跳转及校验保留。

下一题面板保留条件规则、代码块、启用状态和顺序，仍可用 goto/end/complete/full 简写或完整 resolveNext 函数。普通聊天题确认后推进，AI 题按既有完成流程推进。历史 full 配置按当前逐题模式映射，不建立独立的整卷生命周期。

轮播图保留题目编码、图片、高度和自动切换配置，并通过图片复选框收集多选答案，参与必答、进度、逻辑、公式及导出。上传与删除图片位于“选项属性”，高度和自动切换位于“题目属性”，详见[轮播图](http://design.ors-cn.com/agent-help/articles/design/questions/carousel.md)。

## 编码变更检查合同

编码变更应先在独立草稿中分析整份问卷的引用。明确的引用同步更新；动态拼接或不能确认的引用列出所属题目、配置入口、代码位置、原因和修正建议。修正后必须重新检查；只有检查通过并确认影响清单，才能一次应用编码与关联修改。取消或检查失败不改变正式问卷。该检查核心已建立，统一操作入口随后接入。

## 编码变更审核的状态约束

编码变更在独立草稿中检查。取消审核不会改变正式问卷；修正草稿中的代码后，必须再次检查。审核期间若正式问卷发生其他编辑，需要重新发起编码变更，避免覆盖其他修改。动态引用和不能确定的引用必须修正，检查通过并明确确认后才能一起应用。审核窗口显示自动同步记录与阻塞问题。点击“定位并修正草稿”编辑对应入口，再点击“重新检查”。全部通过后勾选影响确认，点击“确认并应用变更”，最后保存问卷。审核期间暂停自动保存。

审核支持明确的 `isSelected("编码")`、集合字面量检查和无歧义的矩阵行列编码引用。编码经未知变量、函数或外部数据传递时，需要在草稿中改为能确定引用的写法；修正后重新引入旧题目名称仍不能通过审核。

题目改码或删除后，原编码保留给原实体，不能分配给其他题目。原题可以改回自己曾用的编码；旧名称不会作为运行别名继续使用。

编码改名不会自动改写可能被局部变量或原生全局捕获的题目引用。遇到此类提示，使用 `context.questions["新题目编码"]` 明确访问；动态 context 属性或 `globalThis` 访问也需改成可静态核对的引用，再复检和确认。switch 内的局部对象及辅助函数的普通参数保持原语义，只有实际脚本入口参数作为平台 context。

题目倒计时优先于[答题时间安排](http://design.ors-cn.com/agent-help/articles/collect/settings-schedule.md)中的全局倒计时。明确设为 0 秒表示不等待；未设置时继承已启用的全局值。

## 题目附件

在基本属性开启“题目附件”，答题者可随题上传补充材料。可设置图片限制、大小范围、最少数量、同名附件及缩略图。仅此属性允许单文件最大 100MB，其他上传保留原限制。详见[题目附件](http://design.ors-cn.com/agent-help/articles/design/properties/attachments.md)。

## 图形校验与答案校验代码

题目逻辑新增“校验逻辑”页签，可配置失败条件、重试次数和红字提示语。0 次立即筛选，1 次提示一次后在下一次仍失败时筛选，2 次提示两次。筛选复用结束提交，但不再执行下一题逻辑；图形规则先于系统必答检查，系统校验通过后才执行布尔答案校验代码。

页签内“自定义校验代码”与基本属性“答案校验逻辑”打开同一编辑器。代码返回合同不变，重试筛选由图形规则配置；三类图形逻辑共用包含／不包含选项和正则判断。操作与边界见[校验逻辑与重试筛选](http://design.ors-cn.com/agent-help/articles/design/logic/visual.md#校验逻辑与重试筛选)。

## 答案预填代码

在题目基本属性中，使用“答案预填代码”声明 initializeAnswer(context)，可异步读取宿主允许的接口，返回 `{mode:"show", answer:初始答案}`，或者 `{mode:"autoComplete", answer:初始答案}`。自动完成仍经过系统校验、自定义答案校验和下一题逻辑。仅能返回本题答案或用已有方法修改本题，不能两种方式同时写入，也不能修改其他题、结构、显示条件或共享变量。

自动完成的题目不占受访者看到的题号；初始化代码返回 `autoComplete` 与自动选择的“直接通过”遵循同一规则，后续显示题目连续编号，恢复草稿后仍保持一致。返回 `show` 的预填题需要受访者作答或确认，照常占用题号。题目编码、答案保存、校验、逻辑与配额仍按原题目身份执行。

首次实际进入且没有恢复或人工回答时，先提供静态默认值，再运行预填，最后沿用现有自动勾选和显隐清理。返回、恢复草稿、主动清空或隐藏后再次出现不重新预填。失败或取消不记成功，可明确重试；请求过期不覆盖较新的人工回答。上传、签名等平台管理数据不能用预填伪造。

## 五个代码入口如何选择

五个按钮分别负责 CSS、预填、渲染、校验和跳转。先选择正确入口，再核对真实题目／选项／矩阵行列编码。显示与隐藏请使用显示代码或图形条件，不能用题目渲染逻辑代替。

- 只改颜色、字号等：自定义 CSS。CSS 按实际选择器作用，平台不会自动把规则限制在本题，也不会自动替换 `{id}`；`question_<内部ID>` 使用内部题目身份，不是 Q1 等题目编码。每种设备保存后都应观察实际效果。
- 第一次出现时填入答案：答案预填代码。先确认本题答案是文本、数字、选项还是矩阵结构。
- 根据前题改变本题标题或选项文案：题目渲染逻辑，只返回 `view`。
- 不符合要求就提示并停留：答案校验逻辑，严格返回 `true` 或 `false`。数字 0 不是空白，避免用 `!context.answer` 直接判空。
- 回答确认后跳题或结束：跳转逻辑。`end()` 表示筛选结束，`complete()` 表示正常完成，`full()` 表示配额满；不能在渲染逻辑中调用。

用户可通过 [AI 使用助手](http://design.ors-cn.com/agent-help/articles/quick-start/assistant.md) 获取代码、粘贴入口和测试步骤。普通编译通过不等于行为正确，应分别测试命中、不命中和未答，并在保存后模拟答题。
