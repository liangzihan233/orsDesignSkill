# 零基础带做

## 第一次交流

先用一句话确认目标：制作并收集问卷、修改已有问卷，还是学习逻辑。询问当前在哪一页或已经做到哪一步即可。用户只想问一个按钮时直接回答，不强制走教程。

## 第一份小问卷

用明确标为“练习”的小问卷说明，所有创建和保存由用户操作，除非用户另外要求代操作。

1. 我的问卷 → 创建问卷，填写名称。成功标志：能进入该问卷编辑工作区。
2. 添加单选 Q1“是否愿意说明原因”，记录真实编码；选项 A1/A2 仅在用户实际采用这些编码时使用。添加填空 Q2“原因”。成功标志：题卡、基本属性及选项内容一致。
3. Q2 题目逻辑 → 显示逻辑，设置 Q1 选中“愿意”才显示。先演示图形设置，再按需解释生成的布尔条件。成功标志：愿意显示，不愿意隐藏。
4. Q2 设置必答。先通过内置必答，不引入无必要代码。成功标志：可见时空答不能继续，隐藏时不被要求作答。
5. 保存后按当前测试入口进行模拟答题。分别检查两条分支、返回修改答案、刷新读取保存设计和手机样式；不要把局部测试当成正式答卷写入。
6. 解释测试发布、预发布和正式发布的区别，再指导用户根据目的选择。分发前检查发布状态及收集链接，避免把编辑、测试、只读分享与答题链接混用。
7. 用测试数据说明结果数据、状态筛选、配额进度、导出及题目编码 sheet。真实收取前确认问卷结构锁定与停止收集后修改的流程。

每一步只给当前所需操作、成功标志及下一步；用户遇到问题则停在该步排查。

## 术语翻译

- 题目编码：供逻辑引用的稳定名称，不是受访者看到的连续序号。
- 显示条件：控制看不看得到题或选项；渲染文案：看得到时显示什么字。
- 预填：先放入本题答案；校验：检查答案是否允许继续；跳转：确认答案后决定下一步。
- 公式变量：可复用的计算值；配额：哪些人能被收取及收取多少，不等同前端显示计数。
- 保存：保存编辑配置；发布：建立可用于收取的版本；提交：受访者交付答案。
